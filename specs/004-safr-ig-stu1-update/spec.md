# Feature Specification: Update SAFR IG Version to STU 1

**Feature Branch**: `004-safr-ig-stu1-update`  
**Created**: 2026-04-02  
**Status**: Draft  
**Input**: User description: "update the script's conformance from SAFR IG version 1.0.0-ballot to this: 1.0.0 | STU 1 (Trial-use) | 2026-04-01"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Convert CSV using STU 1 profile version (Priority: P1)

A data submitter runs the converter against a hospital bed capacity CSV file and receives FHIR Bundle output that declares conformance to SAFR IG version `1.0.0` (STU 1, Trial-use) instead of `1.0.0-ballot`.

**Why this priority**: This is the core change — all generated FHIR resources must reference the official STU 1 release version. Without this, output will reference the superseded ballot version and fail validation against the published IG.

**Independent Test**: Can be fully tested by running the converter on any valid bed capacity CSV and inspecting the output JSON for version `1.0.0` in all profile URLs, measure references, and bundle metadata.

**Acceptance Scenarios**:

1. **Given** a valid bed capacity CSV and the default configuration, **When** the converter runs, **Then** all profile URLs in the output FHIR Bundle reference version `1.0.0` (not `1.0.0-ballot`).
2. **Given** a valid bed capacity CSV, **When** the converter runs, **Then** the MeasureReport bundle profile, submitting organization profile, and Measure URL all use version `1.0.0`.

---

### User Story 2 - Validate output against published STU 1 IG (Priority: P1)

A developer or CI pipeline validates the generated FHIR Bundles against the published `hl7.fhir.us.safr#1.0.0` IG package and receives zero validation errors.

**Why this priority**: Validation against the correct IG version is essential to confirm that the version update is complete and correct, and that no structural changes in the STU 1 release break existing output.

**Independent Test**: Can be fully tested by running the FHIR validator with `-ig hl7.fhir.us.safr#1.0.0` against generated output and confirming zero errors.

**Acceptance Scenarios**:

1. **Given** FHIR Bundle output generated by the updated converter, **When** validated against `hl7.fhir.us.safr#1.0.0`, **Then** zero validation errors are reported.
2. **Given** the CI validation pipeline, **When** it extracts the IG version from the converter source, **Then** it resolves to `1.0.0` and uses the correct IG package for validation.

---

### Edge Cases

- What happens if the FHIR validator cannot resolve the `hl7.fhir.us.safr#1.0.0` package (e.g., not yet published to the registry)? The converter should still produce correct output; validation availability is an external dependency.
- Are there any structural differences between the ballot and STU 1 profiles that require changes beyond the version string? This must be verified during implementation.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The converter MUST set its internal IG version constant to `1.0.0`.
- **FR-002**: All generated FHIR profile URLs MUST reference version `1.0.0` (bundle profile, organization profile, measure URL).
- **FR-003**: The version format validation logic MUST continue to accept the `1.0.0` version string.
- **FR-004**: Generated FHIR Bundles MUST pass validation against the `hl7.fhir.us.safr#1.0.0` IG package with zero errors.
- **FR-005**: No other functional behavior of the converter MUST change — only the IG version reference is updated.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% of generated FHIR Bundle output references IG version `1.0.0` in all profile and measure URLs.
- **SC-002**: FHIR validation of all test fixture outputs against the STU 1 IG produces zero errors.
- **SC-003**: All existing test CSV fixtures convert successfully without errors after the version update.

## Assumptions

- The SAFR IG STU 1 release (`1.0.0`) does not introduce breaking structural changes to the profiles used by this converter (bundle, organization, measure report). If it does, additional spec work will be needed.
- The `hl7.fhir.us.safr#1.0.0` package is available (or will be available) on the FHIR package registry for validator resolution.
- The version change is a single-constant update in the converter source; all profile URLs are derived from that constant.
