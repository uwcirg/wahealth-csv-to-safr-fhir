# Phase 0 Research: Relocate test fixtures

All Technical Context items are known (no NEEDS CLARIFICATION). This document records the few
decisions that shape the implementation.

## Decision 1: Move fixtures with `git mv` (history-preserving)

- **Decision**: Relocate `input/*.csv` to `test/input/*.csv` using `git mv` so each file's
  history follows it.
- **Rationale**: FR-001 requires preserving version-control history. `git mv` records a rename;
  a copy+delete would orphan history and inflate the diff.
- **Alternatives considered**: Copy then `rm` (loses rename detection / blame continuity);
  leaving files in `input/` and symlinking (adds a moving part, breaks on checkout across
  platforms, violates FR-002 "no duplicate copies").

## Decision 2: Achieve test/output routing via `--output-dir`, not a code change

- **Decision**: Keep `convert.py`'s default `--output-dir ./output`. Route regression output to
  `test/output/` by passing `--output-dir test/output` in CI and in the documented pipeline.
- **Rationale**: FR-004 requires the production default to stay `./output`. The converter
  already accepts `--output-dir`; the constitution frames `test/output/` as a *procedural* rule
  for how fixtures are run, not a converter behavior. This keeps `convert.py` untouched
  (Single-File Simplicity, Zero-Dependency Runtime) and avoids fragile auto-detection of the
  input path.
- **Alternatives considered**: Auto-detect `test/input/` in the source and switch output dir
  (couples the converter to a test convention, adds branching to the conformance-critical path,
  surprises production users); change the default to `test/output` (breaks production runs,
  violates FR-004).

## Decision 3: Git-ignore `test/output/`

- **Decision**: Add `test/output/` to `.gitignore` next to the existing `output/` entry.
- **Rationale**: FR-008 + edge case "generated test output committed by accident". The output
  tree is regenerated by every pipeline run; committing it would create churn and risk leaking
  derived data.
- **Alternatives considered**: Commit a `test/output/.gitkeep` and ignore contents (unnecessary
  — the directory is created on demand by the converter); ignore nothing (lets generated JSON be
  committed accidentally).

## Decision 4: CI validator discovery still uses `find`

- **Decision**: In CI, keep the `find <root> -name '*.json'` approach, changing the root from
  `output` to `test/output`.
- **Rationale**: The per-facility subdirectory layout means `**` globbing only works with
  `shopt -s globstar`; `find` reliably reaches `test/output/{date}/{facility}/*.json`. The
  existing CI comment already explains this; only the path changes.
- **Alternatives considered**: `test/output/**/*.json` (requires globstar; brittle).

## Decision 5: README scope — update only fixture/test-path references

- **Decision**: Update README only where it references the regression-fixture directory or the
  test workflow. Leave generic usage examples that use a placeholder input filename and the
  production `./output` default unchanged.
- **Rationale**: FR-009. The README's `python3 convert.py input.csv ... --output-dir ./output`
  examples describe *production* usage with a placeholder filename, not the fixtures directory,
  so they remain correct. Inspection of README found no section that points at the `input/`
  fixture directory by name, so the README edits may be minimal or none — confirm during
  implementation and document either way.
- **Alternatives considered**: Rewrite all `./output` references to `test/output` (wrong —
  conflates production default with the test convention, misleads hospital users).

## Validation impact

The generated FHIR content is identical before and after the move (only its root directory
changes), so the existing known-upstream-issue filters and the "zero project-introduced errors"
gate continue to apply unchanged. The four-step LLM/CI validation pipeline must be re-run after
the relocation to confirm green, per the constitution's mandatory validation requirement.
